# Steel Onslaught — Canonical & Viral Finish Audit

Status: audit findings (advisory)  
Baseline: `main` @ `4752a7f`, worktree branch `docs/so-finish-plan` (2026-07-21)  
Method: 15 subsystem auditors → independent adversarial verifier per area → synthesis (dynamic fan-out workflow, run `wf_c469afe8-eb9`, 31 agents, 0 errors, ~4.85M tokens)  
Findings: **90 confirmed** after skeptic refutation (**6 blocker / 12 high / 32 medium / 40 low**; 89 CONFIRMED, 1 UNCERTAIN; 8 refuted and dropped)

Every finding cites a real `file:line` with a code/behavior excerpt and was re-checked by a second agent instructed to refute it. This report ranks the survivors and maps each to a finish-plan phase.

## Executive summary

The event-sourced substrate is genuinely solid — closed `extra="forbid"` payloads, UUID-preserved correlation, a strict append-only SQLite ledger with DB triggers, deterministic reducers, a real fixture-parity harness between the Python events and the TypeScript parser, and disciplined DI in the composition graph. The auditors were unable to break the core physics or the envelope closedness. The problems are not in the primitives; they are at the **seams**, in the **shipped default demo overlay**, and in **unwired features the finish plan assumes are working**.

**The single biggest thing standing between this and a shareable demo is the seat-identity collapse.** Nine of the fifteen independent auditors converged on it without prompting past the seed anchor: the marquee `tactical_split_v1_qwen` overlay labels the blue seat a `sniper` but binds *both* card programmers to `pilot.llm.qwen35` (persona `berserker`). In paced card mode — the default demo mode — the card programmer, not the loadout pilot, is the decision-maker, and no validator anywhere reconciles the seat's declared archetype with the programmer's actual persona. So the flagship “LLM-vs-LLM” match is **berserker-vs-berserker**: two mechs running the identical “rush to point-blank, fire everything, never vent” prompt, differing only by hand-quota and RNG. The mislabel survives all the way to the ledger (`persona_id=berserker` on the blue seat) and the UI (SpecPanel shows `LLM · berserker` on both rails), while the correct `pilot.llm.qwen35_sniper` sits unused in the same registry directory. This directly falsifies the finish line's central promise of “strategically DIFFERENT trajectories.”

**The finish plan's canonical-architecture claims mostly hold at the model level but not at the boundary level.** `extra="forbid"` is real on individual models, but the event envelope stores payload as an unchecked `FrozenJSONMapping` — closedness is a consumer-side *convention* guarded by a hand-maintained AST allowlist that already misses at least one real raw-payload consumer. “One canonical protocol” is technically true (only SQLite exists) but the *seat-selection* logic has two parallel paths — a validated roster path and an un-validated overlay-programmers path — and the demo runs the un-validated one. The “live learning loop” (P3) does not exist as a running path: `LiveLearningCoordinator` is dead code, has no concrete evaluator, is wired with `promotion=None`, and “promotion” where it happens is an in-memory flag or a YAML file — never a ledger event, so it is neither durable nor replayable. Several terminal-state edge cases (mutual boiler-rupture KO, sudden-death side bias, a two-round heat-lock) produce no winner, an unfair winner, or a mid-match crash.

Net: the substrate is demo-grade; the *product* is not, because the one thing a viewer would screenshot — two visibly different AI personalities fighting, with their reasoning legible — is exactly what the current default path fails to deliver.

## Systemic themes

### 1. Seat identity is not one validated contract (the anchor, everywhere)
*Findings:* match-composition-01, llm-providers-01, projections-cli-01, contracts-data-01/02/03/04/06, contracts-models-01, cards-01/03, match-runner-fold-02/03, pilots-bus-01, frontend-01, product-viral-01/03/04

The blue “sniper” runs the berserker programmer, the `deck_policy.archetype` field is read by *no* handler (dead cosmetic data), the variety handler list is empty (`handler_ids: []`), and both seats draw from identical decks so the only real difference is a 3/2-vs-2/3 hand quota. It is not one bug — it is a missing invariant. **Fix direction:** add a fail-closed composition-time validator that requires each programmer's resolved persona to equal its seat's archetype and requires the two seats to resolve to distinct personas; apply the seat->option pilot rebind on the roster/overlay path, not only the `--catalog-index` path; bind blue to `pilot.llm.qwen35_sniper`; and drive a cross-boundary regression overlay → programmer → `LLM_COMPLETION_REQUESTED` asserting the blue persona is `sniper`.

### 2. Deterministic fallback is the silent default, not an explicit failure mode
*Findings:* contracts-models-02, match-composition-04, llm-providers-02, projections-cli (fallback), product-viral-05

The demo overlay sets `failure_policy: fallback` on both seats; a malformed or failed live completion is silently replaced by the deterministic priority planner, and `plan_committed` carries no provenance field, so the folded/authoritative evidence cannot tell an LLM match from a deterministic one. This is the exact inversion the finish line forbids. **Fix direction:** ship the demo with `failure_policy: raise`; add a typed `plan_source: Literal['llm','deterministic_fallback']` to `ModelSOPlanCommittedPayload` so any degradation is durable and replay-detectable.

### 3. The live learning loop is dead code and non-durable state
*Findings:* learning-adaptation-01/02/03/04

`LiveLearningCoordinator` is never instantiated in production, has no concrete `LiveLearningEvaluator`, and its admission (`begin_match`) and terminal (`handle_after_match`) halves are not on the same port — wiring it as-is would crash every scored match. Promotion is a `current_policy = next_policy` mutation or a YAML file, never a `SOEventType` event, so it violates R5 (state must fold from events) and depends on wall-clock ordering recorded nowhere. **Fix direction:** either wire it correctly with a `POLICY_PROMOTED` event and an admission<->terminal seam, or explicitly declare learning OFF for the demo overlay and stop claiming P3.

### 4. Terminal-state correctness gaps: no winner, wrong winner, or crash
*Findings:* match-runner-fold-01, reducers-02, cards-02, frontend-02, match-composition-02

Sudden death is side-biased (the lexicographically-later mech always wins with full HP, verified at runtime across seeds); a mutual boiler-rupture KO reaches zero survivors with no terminal event (the most spectacular ending produces an infinite empty-tick loop until the progress gate aborts); two consecutive heat-locked rounds crash the runner; the draw path emits `match_scored` after `match_ended` and the frontend transport hard-throws on it; and a non-boundary worker error leaves the FSM stuck in RUNNING forever. **Fix direction:** resolve simultaneous deaths as draws through seeded initiative; emit a terminal on the >1→==0 transition; rebuild `previous_plan` from resolved (not free-only) registers; treat `match_scored` as a legitimate post-terminal projection; add an explicit FAILED runtime status.

### 5. Closedness and identity evidence are convention, not enforcement
*Findings:* events-envelope-01/02/03, ledger-replay-03, llm-providers-05, contracts-models-03, pilots-bus-06

The envelope accepts arbitrary payloads (no `event_type`<->payload cross-check); the allowlist guard misses `llm/adaptation.py`; the single replay-equality gate compares only `ModelSOMatchState`, which excludes provider/persona/model-output identity, so replay proves *physics* reconstruction, not *provider fidelity*; completion evidence omits `model_identity` and the served model text; split-deck matches emit no card-runtime provenance. **Fix direction:** enforce the payload authority at the boundary; include seat / persona / model-identity / card-runtime hashes in the replay-equality comparison.

### 6. Tests are green on surrogates that dodge the real path
*Findings:* match-composition-06, match-runner-fold-05, cards-05, projections-cli-04, contracts-data-05, frontend-03, learning-adaptation-04, reducers-03, pilots-bus-06, projections-cli-05

The no-cap test asserts only `LAST_MECH_STANDING`, never the winning side (masking the sudden-death bias); the rule test uses a hand shape no shipped deck emits; the only “real match” frontend test replays a legacy side-less heuristic ledger; the default demo overlay has zero coverage and the suite actively locks the samey binding in as correct; the evidence-schema release gate passes vacuously with zero tickets. **Fix direction:** add coverage that drives the actual default demo path end-to-end and asserts seat differentiation, winner side, and fallback classification.

### 7. Dead / drifted code that misrepresents what runs
*Findings:* reducers-01, llm-providers-04/06/07, projections-cli-03/06, frontend-04, ledger-replay-08, events-envelope-04/06, product-viral-06, pilots-bus-05

A dead second `ReducerModeTransition` semantic path; an effect-node contract naming a handler class that does not exist; a defined-and-tested-but-never-mounted REST replay endpoint; a dead frontend view cluster with a test certifying an unmounted component; a `human.py` docstring that lies about being unwired; stale 40x40 arena defaults while the demo is 60x60. **Fix direction:** delete or wire; a validated-but-unread contract field is worse than none.

## What stands between this and going viral

The design promises a genuinely shareable artifact: two named AI personalities fighting on a steampunk arena, with a “living Event River” where you watch each LLM's reasoning stream by. The auditors found that substrate largely built — and then found that the default demo path does not deliver the payoff:

- **The two fighters are the same brain.** (product-viral-01, cards-01, match-runner-fold-02) Both seats run the berserker persona over identical decks. There is no visible personality contrast to screenshot — the “sniper vs berserker” framing is a label. This is the whole viral hook, and it is inert.
- **You cannot watch the LLM think.** (product-viral-02, frontend-05) In card/paced mode there are zero `pilot_decision_made` events, so the designed decision-row centerpiece — quoted rationale + confidence meter — never renders. The River shows rows literally labeled “plan committed … event” with no reasoning text, and the DECISIONS tally stays 0. The tactical variety that *does* exist in the stream (`plan_committed.rationale`, move-intent direction) is parsed and then dropped on the floor.
- **Matches risk being boring or broken at the climax.** (match-runner-fold-01, reducers-02, commands-gateway-05, contracts-data-07) Passive/symmetric matches converge to an unfair full-HP win for one side; the most dramatic possible ending (double rupture) hangs with no winner; nothing forbids an all-mirror default match; and every card is force-committed so pilots never actually *choose*.
- **The finish is fragile.** (frontend-02, match-composition-02) A drawn match crashes the frontend scorecard; a provider hiccup can wedge the match in “running” forever.

**The highest-leverage viral fix is small and concentrated:** bind the two seats to genuinely different personas (the sniper spec already exists), enable the variety handlers, and render `plan_committed.rationale` as a decision row. That converts “two identical mechs bumping into each other” into “two AI personalities you can watch reason and diverge” — which is the entire pitch. Everything else is correctness hardening around that payoff.
