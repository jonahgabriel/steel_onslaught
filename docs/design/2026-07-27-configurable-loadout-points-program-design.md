## 1. Platform framing (lead with this)

**DESIGN, operator's words, restated verbatim as the framing this document is written under.** This is the third proof domain for the OmniNode platform. RAG proved retrieval workloads; code generation proved build workloads; a configurable game economy proves interactive learned systems — typed component contracts, purchase events on the bus, deterministic replay of procurement AND battle, build policies promoted through the same ledger. Same machinery, third genre. The whole point of steel_onslaught is showing the platform works for games as well as RAG or codegen.

**Why this framing is not aspirational — it is anchored in ground truth already proven this program (§0):** the bus, the event ledger, and deterministic replay are not new claims for this document to justify — PR #123 already promotes policies as hash-linked, replayable ledger events (§0.7), and the offline evaluator already compares two opaque parameter sets by seed (§0.6). What this program adds is a **second kind of typed object riding that same machinery** — a purchased loadout instead of a tuned deck-knob set — and a **second kind of event on the bus** — a purchase, preflight to the battle events that already flow through it. If that lands, "the platform does games too" stops being a slogan and becomes a replay-provable claim: procurement and battle are both deterministic, event-sourced, and gated by the same promotion ledger.

## 2. Thesis

**DESIGN.** Replace the fixed brawler-vs-sniper dichotomy with a configurable mech + points-budget purchase system in which models assemble their own loadouts preflight. Archetypes become **emergent regions of a typed build space**, not hardcoded classes. Balance relocates from stat knobs (§0.1, a falsified program) to a measurable price list: "no legal list dominates" is tournament-testable, and a dominant build is a pricing signal or a published finding — never a design failure.

This is a direct consequence of §0.1: the fixed-deck knob program is closed on evidence, not on fatigue. Depth (over-deal, §0.3) already showed selection over a decision space is where intentful, divergent behavior comes from. A points-budget build space is the same bet at a higher altitude — instead of selecting cards from a dealt hand, models select components from a catalog under a budget, before the match instead of during it.

## 4. Core design

1. **Typed, priced, versioned component contracts.** Chassis, weapon/armor/card slots, each a contract-declared component with stats + price. Start TINY: one chassis, 2-3 slots, a handful of components — the space grows by versioned addition only (old replays must stay valid; never edit existing arenas/components — new versions only, the same discipline the source design doc applies to arenas, §0.8 there). Per §0.11, this reuses the existing catalog's shape (`contracts_data/chassis/`, `contracts_data/boilers/`, `contracts_data/weapons/`) rather than inventing a parallel one — the new surface is a `price`/`points_cost` field on the component contracts, not a new catalog format.
2. **Points-budget purchase preflight.** Models assemble a legal loadout under budget before the match. Purchases are events on the bus through the platform path — the same governance as every other match-terminal event (§6).
3. **Legality constraints do the first 80% of balancing BEFORE prices.** Tonnage/heat/slot budgets, BattleTech-style hard constraints. Degenerate-build discovery by models is a science feature that needs legality rails, not price whack-a-mole. Per §0.10, three of these rails (mass, slots, pressure headroom) already exist and already run as a fail-closed preflight gate (`_require_valid_budgets`, `match/runner.py:1824`, called from `match/composition.py:2313-2314`) — this item's net-new work is adding a fourth, priced axis to the same validator, not building legality checking from nothing.
4. **Two-level learning (the scientific core).** Inner loop = per-tick play policy (exists today). Outer loop = loadout as a compact, typed, promotable policy object. Per §0.6, the existing offline evaluator protocol signature `evaluate(candidate_params, parent_params, seeds)` (`src/steel_onslaught/learning/duel_evaluator.py:101-105`) is already build-evaluation shaped. Per §0.7, the learning spine (`LiveLearningCoordinator`, `POLICY_PROMOTED`, L-GATE-1 passed at PR #123 @ `7dc970e`) promotes builds with a new params type — no new concept.
5. **New measurables this unlocks** (preregisterable arms in the existing battery methodology, following the same pre-registration/manipulation-landed/contamination-gate discipline as §0.4-§0.5):
   - **Price-elasticity of purchasing** — price-ladder arms, same shape as the vp_per_deploy dose ladder (§0.5): does keep-rate/pick-rate for a component respond monotonically to its price, or does it show its own interior structure?
   - **Meta convergence vs cycling** — build-diversity entropy over generations of the outer-loop learning process (§4 item 4): does the promoted population converge on one build, or does it cycle among several as counters emerge?
   - **Cross-model build fingerprints** — model-vs-model legibility: which LLMs colonize which regions of build space, read the same way over-deal already reads archetype-divergent card selection (§0.3).
   - **Shop-display salience** — the OBJ-MASK/DECOY salience lineage (§0.4) applied directly to the price list: does a model's purchase respond to what is priced, or to how prominently it is shown?

## 8. Cautions (negatives first-class)

- **Points systems are NOT self-balancing.** 40K erratas perpetually re-price the same units; BattleTech Battle Value is the closer genre precedent — a decades-old, continuously-revised points system that has never converged on "no dominant list, permanently." Expect the same here: pricing is an ongoing measurement discipline, not a one-time calibration.
- **The repo already has direct, load-bearing evidence for this caution, independent of any external genre precedent.** Per §0.9, `heat_cost` (`ModelSOCard`) and `points_used`/`points_max` (`ModelSOLoadoutBudgets`) are BOTH declared-but-inert pricing axes that have sat unenforced since their respective designs — one card-level, one loadout-level, designed months apart, never wired to an enforcement path until something outside pricing itself (this program) picked them up. A price field existing in a contract is not evidence that pricing is doing any balancing work.
- **The price list is the new knob program UNLESS pricing stays measurement-driven** — win-rate-vs-cost curves, dominance tournaments — never hand-feel. The same discipline that closed the single-lever knob program (§0.1: measure, decide, stop is a legal outcome) applies here from day one, not as a retrofit after a hand-tuned price list turns out to dominate.
- **First batteries may show models building incoherently.** That is a finding with a display-remediation path (§0.4, the OBJ-MASK/DECOY salience lineage already proves display-necessity for a structurally similar prompt-driven mechanism), not a failed premise. Before re-pricing a component that looks under- or over-picked, check the shop-display salience arm (§4 item 5) first.

## Speculation register (explicitly NOT established)

1. That a priced component catalog produces measurable, non-degenerate build diversity at current model capability — this is the L1 gate's central open question, unproven by anything cited above.
2. That price-elasticity behaves monotonically rather than showing its own interior structure — §0.5 is the closest available precedent (an incentive-dose ladder with a genuine interior peak), and it argues the opposite: expect non-monotonic responses until measured.
3. That the composition fold this program needs (§6 row 1) is a strict subset of what Phase-3 drafting needs, rather than requiring reconciliation once both are built — both consume the same event types today, but neither has been built, so the claim of "shared, not new" work is a design bet, not yet an OBSERVED fact.
4. That a purchased-loadout params type slots into the existing promotion chain (§6 row 5) without protocol changes — plausible from the signature match (§0.6), but the offline evaluator has never been driven with anything but deck-knob parameters; this is untested composition, not proven interchangeability.
5. That N-pilot delegation (L3) is affordable at the same per-match cost the salience arms measured on 1v1 — the delegation path is proven at 1v1 scale (OMN-15154); its cost curve under multi-pilot fan-out is unmeasured.
